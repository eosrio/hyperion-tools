# Hyperion 4.5 release matrix: primary-source research

Research for [tools #20](https://github.com/eosrio/hyperion-tools/issues/20), checked 2026-10-23. This note proposes finite qualification rows; it does **not** prove any row. The operator subsequently selected **v4.1.0, v4.0.8 and v3.3.10-1** as supported upgrade sources and **both Elasticsearch 8.x and 9.x retained-history lanes**. For v3.3.10-1, the no-full-reindex path covers **7.x-created indices**; pre-7-created indices require a separate migration outside this matrix. Exact source-server fixtures and passing compatibility evidence remain open. The [architecture](https://github.com/eosrio/hyperion-tools/blob/de9f589b88a04ce2e4d11d5e08e0a3c00bf6bf2d/docs/architecture/hyperion-4.5.md), [roadmap](https://github.com/eosrio/hyperion-tools/blob/de9f589b88a04ce2e4d11d5e08e0a3c00bf6bf2d/docs/roadmap/hyperion-4.5.md), and [issue #20](https://github.com/eosrio/hyperion-tools/issues/20) remain the authority for release obligations. In particular, retained Elasticsearch history without a mandatory full history reindex, complete AtomicAssets/AtomicMarket parity, working Wire support, reversible-head state by default, and an optional per-chain irreversible-only state mode are release requirements, not outcomes established here.

These are product constraints, not a substitute for testing Hyperion's exact 8.19.1 requests and retained indices. The source releases U1/U2 and v3.3.10-1, plus Elasticsearch 8.x and 9.x history, are now selected. The operator bounded the 3.3.10-1 no-reindex path to 7.x-created indices. A claim that every preexisting Elasticsearch dataset can move in place to 9.5.5 while remaining fully writable/queryable would conflict with Elastic's [index compatibility rule](https://www.elastic.co/docs/deploy-manage/upgrade/plan-upgrade). A valid 3.3.x path can keep 7.x-created indices on a qualified 8.19.23 server, which Elastic documents as having [full query and write support for previous-major indices](https://www.elastic.co/guide/en/elasticsearch/reference/8.19/setup-upgrade.html). Pre-7-created indices require separately documented migration and are outside this matrix. No retained-history path has been qualified here. A Hyperion no-full-history-reindex promise must not be conflated with a claim that every Elasticsearch major upgrade needs no index conversion.

The accepted architecture selects one state backend **per chain**, with independent state/history progress; it does not require one common state/history block. Reversible-head state is the default, and irreversible-only is optional per chain. ## Public state-query surface to preserve or deliberately migrate

At the published v4.1.0 source, [`/v2/state/get_table_rows`](https://github.com/eosrio/hyperion-history-api/blob/a11de79438a26434ea9024a89d877efa8272e22d/src/api/routes/v2-state/get_table_rows/get_table_rows.ts) directly addresses a MongoDB `contract-table` collection. It accepts `contract`, `table`, `scope`, `primary_key`, block ID/number/time and payer; `filters` is JSON passed into the Mongo query after limited date comparison processing; `sort_by` names a field, `sort_direction` is asc/desc, and `skip`/`limit` paginate while `rows_count` counts the matching rows. The [route schema](https://github.com/eosrio/hyperion-history-api/blob/a11de79438a26434ea9024a89d877efa8272e22d/src/api/routes/v2-state/get_table_rows/index.ts) and [public README](https://github.com/eosrio/hyperion-history-api/blob/a11de79438a26434ea9024a89d877efa8272e22d/src/api/routes/v2-state/get_table_rows/README.md) advertise Mongo operators including `$gt`, `$lt`, `$gte`, `$lte`, `$in`. This is a **public Mongo-shaped filter contract**, not yet a defined portable logical-query subset. Its exact accepted operators, nested/array behavior, date coercion, metadata keys, sort/tie and pagination/count behavior, and invalid-query errors need behavior-capture tests before an adapter replaces the implementation. The README says invalid filters yield 400, whereas the inspected handler sends 500 for generic errors; choose and document the 4.5 public behavior rather than silently freezing either claim.

Other published v4.1.0 Mongo-backed named routes include [`get_proposals`](https://github.com/eosrio/hyperion-history-api/blob/a11de79438a26434ea9024a89d877efa8272e22d/src/api/routes/v2-state/get_proposals/get_proposals.ts) (approval/account selectors and `total`), [`get_tokens`](https://github.com/eosrio/hyperion-history-api/blob/a11de79438a26434ea9024a89d877efa8272e22d/src/api/routes/v2-state/get_tokens/get_tokens.ts), [`get_top_holders`](https://github.com/eosrio/hyperion-history-api/blob/a11de79438a26434ea9024a89d877efa8272e22d/src/api/routes/v2-state/get_top_holders/get_top_holders.ts), and [`get_voters`](https://github.com/eosrio/hyperion-history-api/blob/a11de79438a26434ea9024a89d877efa8272e22d/src/api/routes/v2-state/get_voters/get_voters.ts). These are separate preservation/migration decisions; the presence of `/v2/state` in a route name alone does not prove Mongo backing. Nor does the table route establish equivalence with the chain RPC `/v1/chain/get_table_rows`; the [route's own error text](https://github.com/eosrio/hyperion-history-api/blob/a11de79438a26434ea9024a89d877efa8272e22d/src/api/routes/v2-state/get_table_rows/get_table_rows.ts) sends users there only when a collection is not indexed. [Existing-state source inventory](https://github.com/eosrio/hyperion-tools/blob/de9f589b88a04ce2e4d11d5e08e0a3c00bf6bf2d/docs/architecture/hyperion-4.5-existing-mongodb.md).

## Backend launch boundary and exact pin record

**MongoDB is mandatory for launch** if it is the only qualified state backend. The shared SDK definition and query contract, adapter, actual MongoDB engine, complete AtomicAssets/AtomicMarket parity, chosen chain/finality modes, fork/restart recovery and API behavior all need evidence. The current in-repository MongoDB adapter is a private development package `@eosrio/hyperion-backend-mongodb` **0.0.0-dev.1**, with `mongodb` driver **7.2.0** and a development SDK peer; neither its version nor the E2E `mongo:8` image is an exact supported production engine/adapter pair. [Adapter package at inspected 4.5 commit](https://github.com/eosrio/hyperion-history-api/blob/27b3b1a2d529365473947f92e574d0dbcf665ba0/packages/backend-mongodb/package.json), [E2E Compose](https://github.com/eosrio/hyperion-history-api/blob/27b3b1a2d529365473947f92e574d0dbcf665ba0/tests/e2e/docker-compose.yml), [MongoDB-only allowance](https://github.com/eosrio/hyperion-tools/blob/de9f589b88a04ce2e4d11d5e08e0a3c00bf6bf2d/docs/adr/0007-allow-mongodb-only-45-release.md).

**WormDB remains a permanent alternative but is conditional for the 4.5 launch.** [Tools #23](https://github.com/eosrio/hyperion-tools/issues/23) must establish capability gaps and effort; an explicit release decision either qualifies WormDB on the applicable A-S/A-AA/W-S rows or declares MongoDB-only 4.5 while preserving the backend-neutral definitions. The [assigned WormDB adapter home](https://github.com/eosrio/hyperion-tools/blob/de9f589b88a04ce2e4d11d5e08e0a3c00bf6bf2d/docs/architecture/hyperion-4.5-component-homes.md) is not itself a release or evidence that an engine/adapter pair is ready.

**Proposed tested-set record** for each offered matrix row: immutable Hyperion 4.5 source/release artifact; Elasticsearch server version **and image/build digest**, index-creation versions and mappings, exact JS client version/lockfile; state engine edition/version **and binary/image digest**; independent backend-adapter package version/source commit/artifact digest; SDK and enabled plugin package versions/source commits/digests; Wire node binary/source/genesis/deployed WASM/ABI digests where applicable; chain ID, finality mode, API-domain enablement and fixture/evidence IDs. Keep declared compatibility ranges separate from **tested exact combinations** in the catalog. The [component foundation](https://github.com/eosrio/hyperion-tools/blob/de9f589b88a04ce2e4d11d5e08e0a3c00bf6bf2d/docs/architecture/hyperion-4.5-component-homes.md) explicitly distinguishes SDK, adapter and database engine versions; the [architecture](https://github.com/eosrio/hyperion-tools/blob/de9f589b88a04ce2e4d11d5e08e0a3c00bf6bf2d/docs/architecture/hyperion-4.5.md) requires tested Hyperion pins for independently released components. A floating Docker tag, moving branch or semver range alone is insufficient for a qualified row.
